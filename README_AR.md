# نظام حضور المندوبين — الإصدار 2.0.52

نظام حضور يعمل من الموقع وتطبيق Android، مع ربط Firebase وVercel والتحقق من GPS داخل نطاق الفرع. يدعم Owner والأدمن الأول والأدمن الثانوي والمندوب، مع صلاحيات وفروع وسجل تدقيق وأجهزة موثوقة.

## روابط التشغيل

الموقع الإنتاجي: https://delivery-attendance.vercel.app/

رابط APK الحالي: https://delivery-attendance.vercel.app/delivery-attendance-v2.0.52.apk

ملف الإصدار: https://delivery-attendance.vercel.app/version.json

## الحسابات والصلاحيات

الحساب الابتدائي للـOwner يُستخدم فقط بعد تهيئته من النظام. يجب تغيير كلمة المرور مباشرة وعدم وضع بيانات الدخول داخل GitHub أو ملفات النشر. الـOwner يملك كل الصلاحيات، ويستطيع تحديد صلاحيات الأدمن التفصيلية. الأدمن الأول يستطيع إنشاء حسابات المندوبين حسب إعدادات المشروع، والأدمن الثانوي يعمل ضمن فرعه وصلاحياته المحددة.

## الفروع والموقع

يتم إعداد فروع «المركز»، «الحسينية»، «طويريج» و«الحر» من لوحة الإدارة باختيار النقطة على الخريطة وتحديد نطاق السماح. لا توجد حاجة لإدخال خطوط الطول والعرض يدوياً. يمكن مشاركة الموقع الجغرافي بين المركز والحر عند اعتماد ذلك في إعدادات الشركة، مع بقاء بيانات الفرع ظاهرة في الحسابات والسجلات.

## الحضور والانصراف

تسجيل الدخول والخروج يمر عبر API الخادمي ويتحقق من الفرع والنطاق ودقة GPS. إذا نسي المندوب تسجيل الخروج، يبقى سجل الحضور مفتوحاً حتى بعد مرور أيام، ويظهر زر تسجيل الخروج عند العثور على سجل حقيقي مفتوح حتى لو فُقد مؤشر الحضور المساعد. لا يتم حذف سجل الحضور الحقيقي عند تنظيف المؤشرات الوهمية.

الحضور من الموقع يعمل بعد فتح الموقع من زر الربط داخل التطبيق، ويستخدم GPS المتصفح مع ربط الموقع بالجهاز الموثوق. فتح الموقع من جهاز أو متصفح غير معتمد يرفض العملية ويسجل تنبيهاً أمنياً.

## الأداء والتوسع

قائمة المندوبين مقسمة إلى صفحات من 50 عنصراً، والاستعلامات اللحظية محدودة الحجم. تمت إضافة فهارس Firestore للحضور، ويجب أن تكون الفهارس الأربعة في Firebase بحالة `Enabled`:

- `agentId` ثم `date`.
- `agentId` ثم `checkinTime`.
- `branch` ثم `date` ثم `checkinTime`.
- `agentId` ثم `checkoutTime`.

وجود `firestore.indexes.json` في GitHub أو Vercel لا ينشر الفهارس تلقائياً؛ عند عدم استخدام Firebase CLI تُنشأ من Firebase Console يدوياً. بعد أن تصبح `Enabled` لا تحتاج إلى إعادة بناء APK.

## الإدارة والتحديثات

تتضمن لوحة الـOwner حالة النظام، أعداد الحسابات والحضور المفتوح، تحركات الأدمنية، وصلاحيات الأدمن التفصيلية. ملف `version.json` ونسخة الواجهة ونسخة Android يجب أن تحمل الرقم نفسه. يتحقق `scripts/verify-release.js` من التطابق قبل البناء.

عند رفع تحديث جديد إلى Vercel، يجب وضع `version.json` وملف APK المرقم في جذر النشر. لا يُرفع مفتاح التوقيع أو ملف كلمة مرور التوقيع إلى GitHub أو Vercel.

## بناء إصدار جديد

```bash
cp index.html manifest.json icon-192.png icon-512.png version.json www/
pnpm exec cap sync android
cd android
./gradlew assembleRelease
```

قبل النشر، شغّل من جذر المشروع:

```bash
node scripts/verify-release.js /path/to/app-release.apk
```

يجب استخدام نفس مفتاح توقيع Android حتى يقبل الهاتف التحديث فوق النسخة المثبتة. لا تغيّر `applicationId` ولا تفقد مفتاح التوقيع أو كلمة مروره.

## ملفات سرية

لا ترفع `FIREBASE_SERVICE_ACCOUNT` أو مفاتيح Firebase Admin أو `keystore.properties` أو ملفات `.jks` إلى GitHub أو Vercel. مفتاح Firebase Admin يجب أن يبقى Secret داخل Vercel فقط. ملف `firestore.indexes.json` ليس سراً ويمكن حفظه داخل المشروع.
